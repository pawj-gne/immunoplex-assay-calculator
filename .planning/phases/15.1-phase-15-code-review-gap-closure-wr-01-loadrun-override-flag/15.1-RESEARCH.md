### Pattern 1: Conditional-Field-Write Idiom (WR-02 fix)

**What:** Don't emit a field on a payload when the data isn't available; the repository's existing conditional-write code path (`run.ts:99-101, 198-200`) will skip writing the column, leaving the DB row's column NULL (or untouched on update).

**Why it composes cleanly:** `runRepository.create` already implements `if (data.oldBeadsOverride !== undefined) insertValues.oldBeadsOverride = data.oldBeadsOverride` for all 10 Phase 15 fields (verified at `src/main/db/repositories/run.ts:99-101, 198-200`). Omit a field on `RunCreate` and it lands NULL in SQLite, exactly what we want for the "skip the smoke3 marker" branch.

**Example (WR-02 fix):**

```ts
// Source: composition pattern — current code at useRunSnapshot.ts:138-215 + run.ts:99-101 + 198-200
const masterPanelId = selection.selectedPanel?.masterPanelId ?? null
let auditTrailCaptured = false
let sapeName: string | null = null
// ... other 5 audit-trail locals ...

if (masterPanelId) {
  try {
    const result = await window.electronAPI.masterPanel.getWithReagents(masterPanelId)
    if (result) {
      auditTrailCaptured = true
      sapeName = result.masterPanel.sapeName
      // ... existing happy-path field extraction ...
    } else {
      // D-15.1-01: silent-skip the marker, log a warning.
      console.warn(
        `[buildRunSnapshot] Master panel ${masterPanelId} returned null from getWithReagents — saving without 'smoke3' marker.`
      )
    }
  } catch (e) {
    // D-15.1-01: same silent-skip on IPC throw. Don't surface error to user.
    console.warn(
      `[buildRunSnapshot] IPC failure fetching master panel ${masterPanelId} — saving without 'smoke3' marker: ${(e as Error).message}`
    )
  }
}

return {
  // ... 24 existing always-emitted fields ...
  // Phase 15 audit-trail fields — emitted ONLY when capture succeeded (D-15.1-02 gate).
  ...(auditTrailCaptured && {
    sapeName,
    sapeConcentration,
    beadsDiluent,
    antibodiesDiluent,
    beadsVolumePerWell,
    antibodiesVolumePerWell,
    premixConcentration,
    oldBeadsOverride: calculator.oldBeadsOverride,
    oldAntibodiesOverride: calculator.oldAntibodiesOverride,
    calculationRulesVersion: 'smoke3'
  })
}
```

**Note on the override flags + custom-assay path:** Today, when `masterPanelId === null` (custom assay), the IPC is skipped, all 6 master-panel fields stay null, but `oldBeadsOverride` / `oldAntibodiesOverride` / `premixConcentration` / `calculationRulesVersion` are STILL written (verified at `useRunSnapshot.ts:158-215`). After the WR-02 fix, custom-assay saves continue this behavior (no IPC failure occurred — `auditTrailCaptured` should be true for that path). **Planner decision needed:** does `auditTrailCaptured` start `true` and only flip false on IPC failure, OR start `false` and flip true on either (no IPC needed) OR (IPC succeeded)? Recommended: start `true`; flip `false` only when `masterPanelId !== null && (result === null || IPC threw)`. This preserves D-15.1-01's "treat as legacy custom-assay save" semantics ONLY for the IPC-failure case, and leaves the custom-assay happy path unchanged.

### Pattern 2: Pure-Helper Module + Group Tests (WR-06 fix)

**What:** Add functions to `auditTrail.ts` following the existing `computePeVolumeML` / `deriveDiluentBranchLabel` shape. Pure functions, structural input types, zero I/O, fully unit-testable.

**Example sketch (WR-06 derivation helpers):**

```ts
// Source: extends auditTrail.ts with the same shape as computePeVolumeML at lines 16-30.
import { Decimal } from 'decimal.js'
import { calculateRawVolume, applyOldReagentSubtraction } from '../../../lib/calculator'
import { ceilToTenthML } from '../../../lib/decimal'
import type { ReplicateMode } from '../../../../../shared/constants/calculator'

/**
 * Phase 15.1 WR-06: derive Raw {bead,antibody} volume in mL for the audit trail.
 * Returns null when any input is missing or zero (em-dash render in the UI).
 *
 * Note unit shift: r.volumePerWell on RunRecord is µL; r.beadsVolumePerWell is mL.
 * This helper takes the mL value (the snapshot field), converts to µL, and runs
 * the same calculateRawVolume + ceilToTenthML pipeline the live calculator uses.
 *
 * @param sampleCount    - whole number from RunRecord
 * @param replicateMode  - 'singles' | 'duplicates'
 * @param plateCount     - whole number from RunRecord
 * @param volumePerWellML - mL number from RunRecord (e.g., beadsVolumePerWell)
 *                          NOT to be confused with RunRecord.volumePerWell (µL).
 * @param deadVolumeUL   - µL number from RunRecord (RunRecord.deadVolume)
 */
export function computeRawReagentVolumeML(
  sampleCount: number,
  replicateMode: ReplicateMode,
  plateCount: number,
  volumePerWellML: number | null | undefined,
  deadVolumeUL: number
): number | null {
  if (
    volumePerWellML === null ||
    volumePerWellML === undefined ||
    volumePerWellML === 0 ||
    sampleCount <= 0 ||
    plateCount <= 0
  ) {
    return null
  }
  const { totalWells } = calculateTotalWells(sampleCount, replicateMode, plateCount)
  const volumePerWellUL = new Decimal(volumePerWellML).times(1000)
  const raw = calculateRawVolume(totalWells, volumePerWellUL, new Decimal(deadVolumeUL))
  const ceilUL = ceilToTenthML(raw)
  return ceilUL.dividedBy(1000).toNumber()
}

/**
 * Phase 15.1 WR-06: derive New {beads,antibodies} volume in mL.
 * = max(0, ceil(rawML - oldML, 0.1mL))
 *
 * Reuses applyOldReagentSubtraction which already clamps negative to 0 (D-11).
 * Operates in µL for the subtraction (mirrors calculatorStore.getOutputs:347-351),
 * then converts back to mL for display.
 */
export function computeNewReagentVolumeML(
  rawReagentML: number | null,
  oldReagentML: number | null | undefined
): number | null {
  if (rawReagentML === null) return null
  const old = oldReagentML ?? 0
  const rawUL = new Decimal(rawReagentML).times(1000)
  const oldUL = new Decimal(old).times(1000)
  const { newReagentUL } = applyOldReagentSubtraction(rawUL, oldUL)
  const ceilUL = ceilToTenthML(newReagentUL)
  return ceilUL.dividedBy(1000).toNumber()
}

/**
 * Phase 15.1 WR-06: derive Total {beads,antibodies} volume in mL.
 * = old + new (where new is already clamp-to-zero per applyOldReagentSubtraction).
 */
export function computeTotalReagentVolumeML(
  newReagentML: number | null,
  oldReagentML: number | null | undefined
): number | null {
  if (newReagentML === null) return null
  return newReagentML + (oldReagentML ?? 0)
}
```

### Anti-Patterns to Avoid

- **Don't change the snapshot schema** (D-15.1 anti-pattern carried over from CONTEXT.md). Migration 0009 is final. All 6 WR-06-derived values are computed on read, never stored.
- **Don't introduce a `'smoke3.1'` marker.** All three fixes ship under `'smoke3'`. Legacy `smoke3` rows must continue rendering correctly. Verified: WR-06 helpers gracefully fall back to em-dash on missing inputs, so a pre-15.1 `smoke3` row (with valid 10 fields) gets the 6 new derived rows for free.
- **Don't refactor the snapshot builder beyond WR-02.** One boolean gate; no other cleanup. The IPC-fetch structure (`try/catch` around `getWithReagents`) is correct; only the post-fetch decision logic changes.
- **Don't add `console.error` that crashes the save flow.** Per D-15.1-01, silent-skip is the policy. `console.warn` only — no `throw`, no `return { error }` for the WR-02 null path.
- **Don't mix unit-domain conversions in the helper.** Keep mL-input helpers strict-mL; do the µL ↔ mL bridge in one place. The risk: `r.volumePerWell` (µL) is right next to `r.beadsVolumePerWell` (mL) on the RunRecord type — a planner writing the helper from memory could pass the wrong field. The signature must document the unit explicitly (see helper sketch above).
- **Don't read from `calculatorStore` inside `AuditTrailSection.tsx`** (D-15-01 from Phase 15). The component reads exclusively from `RunRecord`. WR-06 derivation MUST take all inputs from `r.*` fields — never reach into the store.
- **Don't trust `r.replicateMode` shape.** Verified: it's the literal union `'singles' | 'duplicates'` (matches `ReplicateMode` from `shared/constants/calculator.ts`). `calculateTotalWells` already accepts this type; no narrowing needed.
- **Don't omit the local-state mirror init for WR-01.** Per `15-REVIEW.md:99-103`, setting only the store flags in `loadRun` leaves `CalculatorForm.tsx`'s local `beadsOverrideAccepted` / `antibodiesOverrideAccepted` at `false`. The cap modal re-triggers on first interaction. The fix needs BOTH the store flag restore (in `runStore`) AND the local-state hydration (in `CalculatorForm`, via `useEffect`).

## Common Pitfalls

### Pitfall 1: Unit-domain confusion in WR-06 helpers (µL vs mL)
**What goes wrong:** Planner writes `calculateRawVolume(totalWells, new Decimal(r.beadsVolumePerWell), new Decimal(r.deadVolume))` thinking `r.beadsVolumePerWell` is µL like `r.volumePerWell`. Result: `0.05` (mL) passed as if it were µL → raw volume off by factor of 1000.
**Why it happens:** `RunRecord.volumePerWell` is µL (calculator domain — matches `DEFAULT_VOLUME_PER_WELL=25`); `RunRecord.beadsVolumePerWell` is mL (master-panel-derived audit-trail field — Plan 15-03 happy-path test fixture sets `0.05`). Both fields are next to each other on the same type.
**How to avoid:**
- Helper signature explicitly names the parameter `volumePerWellML` (not `volumePerWell`).
- Helper docstring calls out the unit shift explicitly (see Pattern 2 example above).
- Test cases include a happy-path with the PRD-canonical worked example fixture (`volumePerWell=50 µL`, `beadsVolumePerWell=0.025 mL` after IPC) so a unit error surfaces immediately as a 25× discrepancy.
**Warning signs:** A test fails with `Expected 7.4, Actual 0.0074` (factor-of-1000 off) — that's the unit bug.

### Pitfall 2: WR-01 — local React state not initialized from store on mount
**What goes wrong:** Planner adds `calculator.setOldBeadsOverride(run.oldBeadsOverride ?? false)` to `runStore.loadRun` and stops. The store flag is now `true` after load, but `CalculatorForm.tsx`'s local `beadsOverrideAccepted` (line 76) is still `false`. The first time the operator types in the Old Beads field, `beadsExceedsCap = !beadsOverrideAccepted && oldBeads > capML` evaluates true (because local state says no override), and the cap modal re-opens.
**Why it happens:** Phase 15-03 dual-wrote local state + store on `handleOverride`/`commit*` paths, but NOT on the load path. The load path never goes through those handlers.
**How to avoid:** Add a `useEffect` in `CalculatorForm.tsx` (next to the existing display-init effects at lines 60-71) that syncs local accepted state from the store flags. Pattern:

```ts
// Phase 15.1 WR-01: when a run is loaded, the store flags are restored by
// runStore.loadRun. Sync local React state from the store on every change
// so the cap modal does not re-trigger on first interaction after reopen.
const storeOldBeadsOverride = useCalculatorStore((s) => s.oldBeadsOverride)
const storeOldAntibodiesOverride = useCalculatorStore((s) => s.oldAntibodiesOverride)
useEffect(() => {
  setBeadsOverrideAccepted(storeOldBeadsOverride)
}, [storeOldBeadsOverride])
useEffect(() => {
  setAntibodiesOverrideAccepted(storeOldAntibodiesOverride)
}, [storeOldAntibodiesOverride])
```

This is byte-for-byte symmetric with the `handleOverride` dual-write at lines 187-199 of the existing CalculatorForm.tsx. The store is the source of truth; local state is a UI mirror.

**Warning signs:** WR-01 round-trip test passes at the store layer (Group L tests above pass) but Phase 16 UAT Step 8 fails because the modal pops on first interaction.

### Pitfall 3: WR-02 — gate logic must distinguish three branches, not two
**What goes wrong:** Naive fix: "if `result == null`, return error / skip." But the existing custom-assay path (`masterPanelId === null`, no IPC call) also leaves all 6 fields null — and that path SHOULD still write `calculationRulesVersion='smoke3'` because the audit trail is partially valid (premixConcentration null, override flags valid). Conflating "no premix selected" with "premix selected but IPC failed" breaks the custom-assay happy path.
**Why it happens:** The current code has one `if (masterPanelId)` block; inside it, `if (result)` then happy-path-pack. The naive fix replaces only the inner condition.
**How to avoid:** The boolean `auditTrailCaptured` flag must be:
- `true` when `masterPanelId === null` (custom assay — IPC skipped, but we still want the marker; the 6 master-panel fields are legitimately null);
- `true` when `masterPanelId !== null && result !== null` (happy path);
- `false` ONLY when `masterPanelId !== null && (result === null || IPC threw)` — this is the WR-02 case.

Verified by reading `useRunSnapshot.test.ts` "custom assay" test at line 197-221: it asserts `calculationRulesVersion === 'smoke3'` for custom assay. The WR-02 fix MUST NOT regress this test.

**Warning signs:** The existing custom-assay test starts failing after the WR-02 fix lands.

### Pitfall 4: WR-06 — applying ceiling twice
**What goes wrong:** Planner reads "max(0, ceiling(raw bead volume − persisted Old Beads value, 0.1mL))" from D-15.1-05 and applies `ceilToTenthML` to `applyOldReagentSubtraction`'s output. But `applyOldReagentSubtraction` doesn't round — it just subtracts and clamps. Then planner ALSO applies `ceilToTenthML` to the raw input. Result: rounding compounds across steps and the displayed value drifts upward from the live calculator output.
**Why it happens:** `calculateRawVolume` does NOT ceil; `applyOldReagentSubtraction` does NOT ceil; only `calculateFinalVolume` and `ceilToTenthML` ceil. The live calculator (in `calculatorStore.getOutputs`) only ceils at the very end (in `calculateFinalVolume`) — the new/total reagent values flow OUT as raw Decimals. Display-time ceiling happens in the renderer (e.g., `ItemizedVolumeDisplay`).
**How to avoid:** In the audit-trail helpers, follow the same pattern as the live calculator — apply `ceilToTenthML` at the LAST step before display, not at each intermediate. For "Raw bead volume," that means `ceil(calculateRawVolume(...))`. For "New beads," that means `ceil(applyOldReagentSubtraction(rawUL, oldUL).newReagentUL)`. Don't pre-round inputs. (Confirmed pattern: the test fixture `9.83 → 9.9` only ceils on the FINAL value.)
**Warning signs:** Audit trail shows `4.5 mL + 5.0 mL = 9.5 mL` (Total) but live calculator showed `9.4 mL`. Discrepancy = compound rounding.

### Pitfall 5: WR-06 — `oldBeads` mL value exceeds the raw bead volume
**What goes wrong:** Operator typed an override-accepted Old Beads value of `10.0 mL` for a 100-sample run where raw bead volume is `7.4 mL`. The "New beads" derivation produces `-2.6 mL` if you forget to clamp.
**Why it happens:** Override paths legitimately permit over-cap values (the 20% cap is for sanity, not a hard limit).
**How to avoid:** `applyOldReagentSubtraction` already clamps to 0 (D-11; verified at `calculator.ts:128-129`). Use it instead of hand-rolling the subtraction. **Side effect of the clamp:** Total = Old + New = Old + 0 = Old when over-subtracted. The audit trail shows "Total bead volume = 10.0 mL" (the override). This matches what the live calculator shows (per `T-J3`/`T-K1` patterns).
**Warning signs:** Unit test for the override-clamp path returns negative or NaN → clamp not applied.

### Pitfall 6: WR-06 — `volumePerWellML === 0` legacy rows
**What goes wrong:** Pre-Phase-12 rows (or any row with `beadsVolumePerWell = null`) fall through to the derivation. If the helper doesn't null-guard the per-well volume, `calculateRawVolume` is called with `new Decimal(0).times(1000) = 0`, producing `rawVolume = 0 + deadVolumeUL` — non-null but incorrect.
**Why it happens:** Numeric coercion of `null` in `new Decimal(null)` throws; coercion of `0` doesn't.
**How to avoid:** Explicit null + undefined + zero checks at helper entry (already specified in D-15.1-07: "When `volumePerWell` is 0 / NULL ... return `null` from the helper").
**Warning signs:** Pre-Phase-15 run reopens; audit trail shows "Raw bead volume: 2.0 mL" (which is JUST the dead volume) instead of em-dash.

// Source: src/renderer/src/features/run/lib/auditTrail.ts:16-30 (existing pattern)
export function computePeVolumeML(
  finalVolumeML: number,
  sapeConcentration: number | null | undefined
): number {
  const concentration =
    sapeConcentration === null || sapeConcentration === undefined || sapeConcentration === 0
      ? 1
      : sapeConcentration
  const finalUL = new Decimal(finalVolumeML).times(1000)
  const peUL = finalUL.dividedBy(concentration)
  const ceilUL = ceilToTenthML(peUL)
  return ceilUL.dividedBy(1000).toNumber()
}
