# Phase 15.1 Plan 03: WR-01 — runStore.loadRun Restores Override Flags + CalculatorForm Mirrors Them Into Local State Summary

WR-01 fix from `15-REVIEW.md` closed end-to-end: persisted run records carrying `oldBeadsOverride` / `oldAntibodiesOverride` (already round-tripped through the DB since Phase 15-01) now make it back into the renderer store on reopen, and the form-side React state mirrors those flags so the amber "overridden" badge appears AND the cap modal stops re-triggering on first interaction after reopen.

## Objective Recap

Restore `oldBeadsOverride` and `oldAntibodiesOverride` from the persisted `RunRecord` into `calculatorStore` during `runStore.loadRun` (TWO sites — store cascade + form-side mirror useEffect), so reopening a run that was saved with override-accepted values shows the override badge on the form AND does not re-trigger the cap modal on first interaction. Per D-15.1-03/04: write path already works (Phase 15-01 columns + Phase 15-03 packs them); the gap is purely on the read path.

### Test Group naming — existing Group L collision (Plan accommodated, not deviation)

**Found during:** Task 1 RED test authoring.
**Observation:** The file already contains a `describe('Group L: selectionStore.selectPanel cross-checked with calculator state (SMK3-13)')` block at line 963 (nested under the `describe('Phase 14-04 calculatorStore old-reagent extension')` outer scope), and that pre-existing Group L uses test IDs `T-L1` and `T-L2`. The plan repeatedly specifies the new block be named `Group L: WR-01 round-trip — oldBeadsOverride / oldAntibodiesOverride flags (D-15.1-03)` with test IDs `T-L1` / `T-L2`.
**Resolution:** Vitest treats describe blocks as namespaces; sibling top-level describe blocks may contain overlapping `it()` titles without collision. The new Group L is added as a top-level describe (sibling to `Group M: PE volume composes…`), distinct from the existing Group L under Phase 14-04. Test discrimination is by full describe path (`Group L: WR-01 round-trip … > T-L1` vs `Phase 14-04 … > Group L: selectionStore.selectPanel … > T-L1`).
**Impact:** None on functionality. The plan's verify `grep -c "T-L1\|T-L2"` returns 5 rather than 2 (the BRE form would have returned 0 — `\|` is not an alternation operator in basic regex; the plan author likely intended ERE which would return 4 plus 1 reference in the new file's section comment header listing T-L1 and T-L2). The spirit of "2 new tests added" is met: `grep -c "Group L: WR-01"` returns exactly 1 (the new section), confirming the new block is exactly one describe.

### Fixture duplication for new Group L (Plan accommodated, not deviation)
