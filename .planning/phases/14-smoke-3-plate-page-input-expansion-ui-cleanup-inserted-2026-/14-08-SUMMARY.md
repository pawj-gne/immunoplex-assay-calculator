## Deviations from Plan

### 1. [Rule 3 — Blocking issue] Migration filename + path corrected

**Found during:** Task 2 GREEN (migration generation step)

**Issue:** Plan instructed `src/main/db/migrations/0004_runs_setups_and_old_reagents.sql`. Two problems:
- `src/main/db/migrations/` does not exist. Drizzle migrations live at `drizzle/migrations/` per `drizzle.config.ts` (`out: './drizzle/migrations'`).
- Index `0004` is taken (`0004_lame_deathstrike.sql`). Migrations 0000..0007 already exist; the next available index is 0008.

**Fix:** Generated via `npx drizzle-kit generate --name=runs_setups_and_old_reagents`, which emitted `drizzle/migrations/0008_runs_setups_and_old_reagents.sql` plus the matching `meta/0008_snapshot.json` and `meta/_journal.json` idx-8 entry — keeping the migration registry consistent. Statements match the plan's spec verbatim:
```sql
ALTER TABLE `runs` ADD `number_of_setups` real DEFAULT 1 NOT NULL;
ALTER TABLE `runs` ADD `old_beads` real DEFAULT 0 NOT NULL;
ALTER TABLE `runs` ADD `old_antibodies` real DEFAULT 0 NOT NULL;
```

### 3. [Rule 2 — Missing critical functionality] runRepository.update extended (plan only specified create)

**Found during:** Task 2 GREEN repository edit

**Issue:** Plan's `<must_haves>` truths block lists `create` writes + `getById`/`list` reads. It does NOT mention `update`. But `update` and `create` are symmetric — if `update` ignores the three fields, a saved run that gets edited would silently drop the values back to NULL/default.

**Fix:** Extended `update` with the same omit-and-DB-default pattern as `create`. Adds ~6 lines to the existing baseSet/setWithProvenance widening. No new tests added for update (out of plan scope), but the symmetric write path is now in place for Plan 14-07's integration tests.
