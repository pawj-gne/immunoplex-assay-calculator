# 14-08 — DB persistence for numberOfSetups + oldBeads + oldAntibodies

<objective>
Close the inherited DB-schema gap surfaced by 14-04's executor. The `runs` table currently
has columns for sample_count, replicate_mode, volume_per_well, plate_count, etc. — but not
for `numberOfSetups` (Phase 12), `oldBeads`, or `oldAntibodies` (Phase 14). The TypeScript
types + Zod validation already carry these as optional. Without DB columns, save→reload
silently drops the values, breaking SMK3-16 snapshot fidelity for on-disk persistence.

This plan ships the missing DB columns, migration, repository writes, and tests so Plan 06's
UI can ship without persistence regression.
</objective>

<threat_model>
**ASVS L1.** Local Electron app, no network surface. Threats:
- T-1: Migration corruption on existing user DBs → mitigation: ADD COLUMN with NULL/default-0, no destructive ALTER.
- T-2: Read-of-old-record null safety → mitigation: repository.getById returns `undefined` for absent columns; renderer's `?? 0/1` defaults already in place (verified in 14-04 SUMMARY).
- Other STRIDE threats: n/a — local Electron, no network surface in this phase.
</threat_model>
