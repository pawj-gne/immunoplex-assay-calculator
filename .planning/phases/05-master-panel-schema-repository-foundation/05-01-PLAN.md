## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| schema.ts → Drizzle generator | schema.ts is the source-of-truth for DDL; drizzle-kit's emission MUST preserve the composite UNIQUE INDEX and onDelete semantics. Trust-but-verify: grep-verify the emitted SQL (Pitfall 1). |
| Drizzle `$inferSelect` → hand-written shared types | Schema-inferred types (schema.ts bottom) and hand-written `shared/types/*.ts` must agree on nullability, or UI-layer contracts drift silently. Mitigation: run `npm run typecheck` after every edit (Pitfall 5). |
| drizzle/migrations/ → v1 deployed DB | The 0004 migration applies at next boot via `migrate()` on existing production DBs. Any DROP or NOT NULL tightening would cause data loss. Phase 5 is additive-only by design (D-21 uses `.default(1)` so pre-existing rows materialize cleanly). |

| T-05-01-02 | Denial of Service (silent data loss at migration) | 0004_*.sql applied to v1 DB | mitigate | Additive-only migration (no DROP / no NOT NULL tightening); `sub_panel_conc REAL NOT NULL DEFAULT 1` (D-21) ensures pre-existing rows survive; SC #1 integration test in Plan 02 re-asserts on every run |
