The implication: run-load currently never re-applies the saved `deadVolume`; it reapplies `sampleCount`/`replicateMode`/etc. and lets `getOutputs()` recompute volumes from defaults. THIS IS A LATENT BUG predating Phase 12: a run saved with 2 plates and the v1.0 rule (DEAD_VOLUME=2000) would re-render the same dead volume on load — only because the default was hardcoded to match. Under Smoke 3 with `numberOfSetups` variable, that lucky-default protection is gone.

**Decision for THIS plan:** Run-load adds `calculator.setNumberOfSetups(run.numberOfSetups ?? 1)` after `setReplicateMode`. Persisted runs that pre-date Smoke 3 (no `numberOfSetups` field in the serialized snapshot) fall through to the `?? 1` default — equivalent to v1.0 behavior. The "snapshot-frozen" advisory marker UI is Phase 15. Don't change the snapshot SCHEMA in Phase 12 (Phase 15 owns that); just ensure that when a Smoke 3 run is saved + reloaded, the numberOfSetups survives the round trip.

Wait — read useRunSnapshot.ts:101 more carefully. It serializes `calculator.deadVolume` into the run snapshot but does NOT serialize `numberOfSetups`. So a run saved AFTER Phase 12 will round-trip its `deadVolume` (e.g., 6000 µL for setups=3) but NOT its `numberOfSetups`. On reload, the store would set sampleCount/etc. and getOutputs() would recompute deadVolume from `numberOfSetups = 1` (initial default), producing 2000 µL — DIFFERENT from the persisted 6000.

**Decision refined:** Add `numberOfSetups` to the run snapshot JSON via useRunSnapshot.ts:101 area. This is a small additive snapshot schema change. **PHASE 12 SCOPE CHECK:** CONTEXT.md §Domain Phase Boundary says "no DB, no run-doc work". But this is purely an in-memory snapshot JSON field, not a DB migration. The `runs.snapshot` column (or however it's persisted) is open JSON — adding a field is backwards-compatible (old snapshots lack `numberOfSetups`, the load code defaults to 1).

**FINAL decision for snapshot:** This plan WILL add `numberOfSetups` to the JSON shape returned by useRunSnapshot. Justification: without it, the "snapshot-frozen historical runs" principle (SMK3-16) is impossible to satisfy — the dead-volume number on disk would not be reproducible from the on-disk state. This is an enabling tweak, not Phase 15's work (Phase 15 owns the advisory MARKER UI + the audit-trail BREAKDOWN; this is just the input persistence). Document the deviation in 12-03-SUMMARY.md.
