<objective>
Migrate the calculator's rounding and dead-volume rules to the Smoke 3 PRD specification:
1. **Rounding (SMK3-06):** Replace "round up to nearest mL" with "round up to nearest 0.1 mL" (ceiling at 0.1 mL precision). Supersedes CALC-06 and STATE decision 02-01.
2. **Dead volume (SMK3-05, extends CALC-03):** Replace the constant `DEFAULT_DEAD_VOLUME = 2000 µL` model with a formula: `dead_volume_uL = number_of_setups × 2000` (i.e., `setups × 2 mL`). Default `numberOfSetups = 1`.

Purpose: Without these changes shipping together, Smoke 3 calculator math is wrong and downstream phases (13 parser, 14 UI, 15 run-doc) cannot build on a correct foundation.

Output: Updated decimal.ts + calculator.ts + shared types + comprehensive unit tests. **No store or UI changes in this plan** — calculatorStore plumbing of `numberOfSetups` lives in Plan 12-03.

Backwards compatibility:
- `createCalculatorInputs` keeps its existing positional signature but adds `numberOfSetups: number = 1` as the final optional parameter. Existing callsites (calculatorStore line 163, useRunSnapshot line 101 reads only) continue to compile unchanged.
- `CalculatorInputs` interface gains `numberOfSetups: number` as a REQUIRED field (caller responsibility) — but `createCalculatorInputs` always supplies it, so renderer consumers never see the change.
- The old `DEFAULT_DEAD_VOLUME = 2000` constant in `shared/constants/calculator.ts` is RENAMED to `DEAD_VOLUME_PER_SETUP_UL = 2000` to reflect its new meaning (volume contributed per setup). Existing imports update accordingly. This grep-verifiable rename forces callers to confront the semantic shift.
