<objective>
Implement the Smoke 3 concentration-keyed diluent resolver as a standalone module — separate from `lib/calculator.ts` because diluent resolution is a distinct domain concern that will grow as Phase 13 introduces per-reagent panel data, and easier to test in isolation (per CONTEXT §Decisions →Claude's Discretion).

Per SMK3-07 + R-04:
1. If ANY selected premix has Premix Concentration === 1, that premix is the diluent for Beads AND Antibodies.
2. Else: per-reagent fallback — use the Values-table diluent string for Beads and Antibodies separately.
3. Legacy compatibility: if the panel's Values block doesn't expose per-reagent diluents (because it was imported by the v0.7.0 parser which has no diluent fields), the resolver returns `{ kind: 'legacy', beads: null, antibodies: null }`. The caller decides how to display this (e.g., fall back to the existing v1 "Assay Buffer" or render "(legacy panel — diluent unspecified)").

**Tiebreaker decision (multi 1× premixes selected) — RECORDED HERE AS PLAN-LEVEL DECISION:**
When more than one selected premix has concentration === 1, the resolver returns the **first** such premix in the input `selectedPremixes` array order. The CALLER is responsible for passing premixes in a stable order. In Phase 12 the caller will be Plan 12-03's calculatorStore — which itself reads from selectionStore.getSelectedPanel() (panel-defined order — `panel.analytes` reflects panel-authored order, and any future multi-premix selection state will also be order-preserving by the order user selected them). Document this in the function's JSDoc and pick a stable order (input-array order is the simplest, most testable rule).

Rationale for input-array-order over alternatives:
- **Panel-defined order** is what we want semantically, but enforcing it in the resolver would require the resolver to know about panel-data shape — coupling the resolver to PanelWithAnalytes. By making input-array-order the rule, the resolver stays decoupled and the caller (calculatorStore) is responsible for the policy.
- **Alphabetical** is order-stable but ignores the lab's source-of-truth ordering.
- **First-selected** would require a separate "selection order" tracker in selectionStore that doesn't currently exist (would add Phase 12 store work for a degenerate case).

Out of scope for Phase 12 (deliberate, per CONTEXT §Deferred):
- Per-reagent panel data fetching from the DB (Phase 13 SMK3-08 grows master_panels schema). The resolver accepts the per-reagent data as a typed parameter; how the caller obtains that data is not this plan's concern.
- Wiring the resolver into calculatorStore (Plan 12-03).
- UI display of diluent decisions in the run document (Phase 15 SMK3-15).
</objective>

       ```typescript
       import type {
         DiluentResult,
         SelectedPremixForDiluent,
         PanelValuesDiluent
       } from '../../../shared/types/diluent'

       /**
        * Resolve which diluent applies to Beads and Antibodies for the current
        * selection, per Smoke 3 PRD SMK3-07.
        *
        * Algorithm:
        *   1. Scan selectedPremixes in input-array order. If ANY has
        *      concentration === 1, return { kind: 'premix', name: that.name }.
        *      Tiebreaker for multiple 1× premixes: FIRST in array (deterministic;
        *      caller controls ordering — see Plan 12-02 §Tiebreaker decision).
        *   2. No 1× premix found:
        *      a. If valuesTable is provided, return { kind: 'values_table',
        *         beads: valuesTable.beads, antibodies: valuesTable.antibodies }
        *         — strings returned VERBATIM (no normalization per SMK3-DIL-01).
        *      b. Else (legacy v0.7.0 panel) return { kind: 'legacy',
        *         beads: null, antibodies: null }. Caller decides display.
        *
        * The resolver is pure: no I/O, no mutation, no Decimal math. Testable
        * in isolation against plain objects.
        */
       export function resolveDiluent(args: {
         selectedPremixes: ReadonlyArray<SelectedPremixForDiluent>
         valuesTable: PanelValuesDiluent | undefined
       }): DiluentResult {
         const { selectedPremixes, valuesTable } = args

         // Step 1: any 1× premix wins (first in input order on tiebreak)
         for (const premix of selectedPremixes) {
           if (premix.concentration === 1) {
             return { kind: 'premix', name: premix.name }
           }
         }

         // Step 2a: per-reagent Values-table fallback
         if (valuesTable !== undefined) {
           return {
             kind: 'values_table',
             beads: valuesTable.beads,
             antibodies: valuesTable.antibodies
           }
         }

         // Step 2b: legacy panel — no per-reagent diluent data available
         return { kind: 'legacy', beads: null, antibodies: null }
       }

       // Re-export types for callers that want to import from one path
       export type {
         DiluentResult,
         SelectedPremixForDiluent,
         PanelValuesDiluent
       } from '../../../shared/types/diluent'
       ```
