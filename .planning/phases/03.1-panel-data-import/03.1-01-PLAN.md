<task type="auto">
  <name>Task 1: Install xlsx and create parser + validator modules</name>
  <files>
    src/main/import/parser.ts
    src/main/import/validator.ts
  </files>
  <action>
    1. Install xlsx: `npm install xlsx`

    2. Create `src/main/import/parser.ts`:
       - Export `parseImportFile(filePath: string): RawImportRow[]`
       - Use `XLSX.readFile(filePath)` to read file
       - Get first sheet: `workbook.Sheets[workbook.SheetNames[0]]`
       - Convert to JSON: `XLSX.utils.sheet_to_json<RawImportRow>(sheet)`
       - Define and export `RawImportRow` interface with fields: platform, species, panel_name, analyte_name, bead_region, bead_stock_conc, antibody_stock_conc, panel_description (optional)
       - Return the parsed rows array

    3. Create `src/main/import/validator.ts`:
       - Export Zod schema `importRowSchema` matching RawImportRow fields:
         - platform: z.string().min(1)
         - species: z.string().min(1)
         - panel_name: z.string().min(1)
         - analyte_name: z.string().min(1)
         - bead_region: z.number().int().positive()
         - bead_stock_conc: z.number().positive()
         - antibody_stock_conc: z.number().positive()
         - panel_description: z.string().optional()
       - Export `validateImportRows(rows: unknown[])` that returns `{ valid: ValidatedRow[], errors: { row: number; issues: string[] }[] }`
       - Row numbers in errors should be +2 (1-indexed + header row)
       - Export `ValidatedRow` type (z.infer of the schema)
       - Export `validatePlatformsAndSpecies(rows: ValidatedRow[], platforms: {id,name}[], species: {id,name,platformId}[])` that:
         - Does case-insensitive lookup of platform names
         - Does case-insensitive lookup of species names within matched platform
         - Returns `{ resolved: ResolvedRow[], errors: { row: number; issues: string[] }[] }` where ResolvedRow adds platformId and speciesId
         - If platform not found, error message lists valid platform names
         - If species not found for platform, error message lists valid species for that platform
  </action>
  <verify>
    - `npm ls xlsx` shows xlsx installed
    - `npx tsc --noEmit` compiles without errors
    - Both files export their documented functions/types
  </verify>
  <done>Parser reads CSV/Excel to typed rows. Validator validates row shapes and resolves platform/species names to IDs with clear error messages.</done>
</task>

<task type="auto">
  <name>Task 2: Create importer module and extend repositories</name>
  <files>

  <action>
    1. Extend `src/main/db/repositories/analyte.ts`:
       - Add `findByNamePlatformSpecies(name: string, platformId: string, speciesId: string): Analyte | null` - case-insensitive lookup using SQL lower() on name
       - Add `createMany(data: AnalyteCreate[]): Analyte[]` - inserts multiple analytes, returns all created records. Use a loop calling the existing create logic (better-sqlite3 is synchronous so this is fine inside a transaction)

    2. Extend `src/main/db/repositories/panel.ts`:
       - Add `findByNamePlatformSpecies(name: string, platformId: string, speciesId: string)` - case-insensitive lookup
       - Add `create(data: { name, description?, platformId, speciesId }): Panel` - creates a single panel with crypto.randomUUID()
       - Add `addAnalyteToPanel(panelId: string, analyteId: string)` - inserts into panelAnalytes junction table, skips if already exists

    3. Create `src/main/import/importer.ts`:
       - Export `importPanelData(filePath: string): ImportResult`
       - ImportResult type: `{ success: boolean; canceled?: boolean; created: { analytes: number; panels: number; links: number }; skipped: { analytes: number }; errors: { row: number; issues: string[] }[] }`
       - Flow:
         a. Call parseImportFile(filePath) to get raw rows
         b. Call validateImportRows(rows) - if errors, return early with errors
         c. Load all platforms from DB (use a simple select from platforms table)
         d. Load all species from DB
         e. Call validatePlatformsAndSpecies(valid, platforms, species) - if errors, return early
         f. Wrap DB operations in better-sqlite3 transaction (get raw db via `getDatabase().run(sql...)` or use the underlying better-sqlite3 connection's `.transaction()`)
         g. For each resolved row, grouped by panel:
            - Find or create analyte (skip if exists by name+platform+species)
            - Find or create panel (by name+platform+species)
            - Link analyte to panel (skip if link exists)
         h. Return counts of created/skipped
       - For the transaction, access the raw better-sqlite3 instance. Check how getDatabase() works - if it returns a Drizzle wrapper, you may need to use `db.$client` or similar to get the underlying better-sqlite3 database for `.transaction()`. Alternatively, just wrap the operations and if one fails, throw to rollback.
  </action>
