# Phase 3.1: Panel Data Import - Research

**Researched:** 2026-01-29
**Domain:** CSV/Excel file parsing in Electron, bulk data import to SQLite
**Confidence:** HIGH

## Summary

This phase adds CSV/Excel file import for panel data (analytes + panels) across all 4 platforms. The existing codebase already has a well-defined schema (analytes, premix_panels, panel_analytes tables), repository pattern, and IPC handlers. The import feature needs: file dialog, file reading, parsing, validation, and database insertion -- all in the Electron main process.

The recommended approach uses `xlsx` (SheetJS) for parsing both CSV and Excel files with a single library, Zod for row validation (already in deps), and Electron's `dialog.showOpenDialog` for file selection. The import flow runs entirely in the main process via a new IPC channel.

**Primary recommendation:** Use the `xlsx` library to handle both CSV and Excel formats, validate each row with Zod, and insert via existing repository pattern with transaction wrapping.

### Pattern 1: Import Flow (Main Process Only)
**What:** Entire import runs in main process: dialog -> read -> parse -> validate -> insert
**When to use:** Always for this feature

```typescript
// IPC handler
ipcMain.handle('import:panel-data', async (event, options) => {
  // 1. Show file dialog
  const result = await dialog.showOpenDialog({
    filters: [
      { name: 'Spreadsheets', extensions: ['csv', 'xlsx', 'xls'] }
    ],
    properties: ['openFile']
  })
  if (result.canceled || !result.filePaths[0]) return { success: false, canceled: true }

  // 2. Read and parse
  const filePath = result.filePaths[0]
  const workbook = XLSX.readFile(filePath)
  const sheet = workbook.Sheets[workbook.SheetNames[0]]
  const rows = XLSX.utils.sheet_to_json<RawImportRow>(sheet)

  // 3. Validate
  const validated = validateImportRows(rows)
  if (validated.errors.length > 0) return { success: false, errors: validated.errors }

  // 4. Insert in transaction
  const counts = insertPanelData(validated.data)
  return { success: true, ...counts }
})
```

### Pattern 3: CSV Format Definition
**What:** Define a standard CSV format that maps to the schema
**Expected columns:**

```csv
platform,species,panel_name,analyte_name,bead_region,bead_stock_conc,antibody_stock_conc
Milliplex,Mouse,Mouse Premix Panel I 32-Plex,IL-1a,32,20,25
Milliplex,Mouse,Mouse Premix Panel I 32-Plex,IL-1b,47,20,25
```

Key design decisions:
- Use platform NAME not ID (user-friendly; lookup by name in DB)
- Use species NAME not ID (same reason)
- One row per analyte; panel membership implied by panel_name column
- Panel description is optional column
- IDs are auto-generated on import (not in CSV)
- Timestamps are auto-generated on import

### Anti-Patterns to Avoid
- **Parsing in renderer process:** File I/O and DB access must stay in main process
- **No validation before insert:** Always validate every row before any DB writes
- **Individual inserts without transaction:** Use transaction for atomicity and performance
- **Hardcoded platform/species IDs in CSV:** Use human-readable names, resolve to IDs during import

## Common Pitfalls

### Pitfall 1: Duplicate Data on Re-Import
**What goes wrong:** User imports same file twice, creates duplicate analytes/panels
**Why it happens:** No dedup logic
**How to avoid:** Before inserting, check if analyte with same (name, platformId, speciesId) exists. Use upsert or skip strategy. Recommend: skip existing, report to user.
**Warning signs:** Duplicate analyte names in same platform/species

### Pitfall 2: Platform/Species Name Mismatch
**What goes wrong:** CSV says "MilliPlex" but DB has "Milliplex" -- lookup fails
**Why it happens:** Case sensitivity, typos
**How to avoid:** Case-insensitive lookup. Validate platform/species names exist before processing any rows. Return clear error with valid options.

### Pitfall 3: Missing Panel-Analyte Junction Records
**What goes wrong:** Analytes imported but not linked to panels
**Why it happens:** Forgetting to create panelAnalytes records
**How to avoid:** Import logic must create: (1) analytes, (2) panels, (3) panel_analytes junction records -- all in one transaction

### Pitfall 4: Large File Performance
**What goes wrong:** UI freezes during import
**Why it happens:** Synchronous processing blocks main process
**How to avoid:** For this use case (hundreds to low thousands of rows), synchronous is fine. If needed later, could use worker thread. SQLite transactions with better-sqlite3 are very fast for bulk inserts (10k+ rows/second).

### Pitfall 5: BOM in CSV Files
**What goes wrong:** First column name has invisible BOM character
**Why it happens:** Excel exports CSV with UTF-8 BOM
**How to avoid:** xlsx handles this automatically when using `readFile`

## Code Examples

### Reading and Parsing a File
```typescript
import * as XLSX from 'xlsx'

interface RawImportRow {
  platform: string
  species: string
  panel_name: string
  analyte_name: string
  bead_region: number
  bead_stock_conc: number
  antibody_stock_conc: number
  panel_description?: string
}

function parseImportFile(filePath: string): RawImportRow[] {
  const workbook = XLSX.readFile(filePath)
  const sheetName = workbook.SheetNames[0]
  const sheet = workbook.Sheets[sheetName]
  return XLSX.utils.sheet_to_json<RawImportRow>(sheet)
}
```

### Zod Validation Schema
```typescript
import { z } from 'zod'

const importRowSchema = z.object({
  platform: z.string().min(1, 'Platform is required'),
  species: z.string().min(1, 'Species is required'),
  panel_name: z.string().min(1, 'Panel name is required'),
  analyte_name: z.string().min(1, 'Analyte name is required'),
  bead_region: z.number().int().positive('Bead region must be positive integer'),
  bead_stock_conc: z.number().positive('Bead stock concentration must be positive'),
  antibody_stock_conc: z.number().positive('Antibody stock concentration must be positive'),
  panel_description: z.string().optional()
})

function validateRows(rows: unknown[]) {
  const valid: z.infer<typeof importRowSchema>[] = []
  const errors: { row: number; issues: string[] }[] = []

  rows.forEach((row, i) => {
    const result = importRowSchema.safeParse(row)
    if (result.success) {
      valid.push(result.data)
    } else {
      errors.push({
        row: i + 2, // +2 for 1-indexed + header row
        issues: result.error.issues.map(e => `${e.path.join('.')}: ${e.message}`)
      })
    }
  })

  return { valid, errors }
}
```

## Open Questions

1. **Species auto-creation**
   - What we know: CSV will have species names; DB has pre-seeded species per platform
   - What's unclear: Should import create new species if not found, or reject?
   - Recommendation: Reject unknown species with clear error. Species are finite and should be managed separately.

2. **Panel description column**
   - What we know: Schema supports description field
   - What's unclear: Whether to require it in CSV
   - Recommendation: Make it optional. Default to empty string if omitted.

3. **Overwrite vs skip behavior**
   - What we know: Users may re-import with corrections
   - What's unclear: Whether to update existing records or skip
   - Recommendation: Default to skip existing (by analyte name + platform + species). Optionally allow overwrite mode via UI toggle.
