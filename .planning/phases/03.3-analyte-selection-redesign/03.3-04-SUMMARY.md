## Decisions Made
- **Two-state input pattern:** SampleCountInput uses a string `displayValue` for the text field and a number `value` prop for the slider. This avoids typing friction (user can type freely without immediate parsing/clamping).
- **One-directional store dependency:** calculatorStore reads plateCount from plateStore via `usePlateStore.getState().getPlateCount()`. This avoids duplicating plate count state.
- **Propagation on action:** When calculatorStore's `setSampleCount` or `setReplicateMode` is called, it also calls the corresponding plateStore action. This keeps auto-fill in sync.
- **Reset cascading:** `calculatorStore.reset()` also calls `usePlateStore.getState().reset()` to ensure full state cleanup.
