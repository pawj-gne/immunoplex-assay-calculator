**Update `App.tsx` with slide transitions:**

Replace the current instant conditional rendering (`{currentPage === 0 && ...}`) with a transition system using tw-animate-css classes.

Approach: Keep both old and new pages in the DOM during the ~300ms transition. Use a two-phase model:
1. When `currentPage` changes: set `isTransitioning = true`, determine direction (forward if new > old, backward if new < old)
2. During transition: render BOTH old page (with exit animation) and new page (with enter animation) in a relative/absolute container
3. After 300ms timeout: set `isTransitioning = false`, only render new page

State needed:
```typescript
const [displayPage, setDisplayPage] = useState(currentPage)  // what's currently shown
const [isTransitioning, setIsTransitioning] = useState(false)
const [direction, setDirection] = useState<'forward' | 'backward'>('forward')
const prevPage = useRef(currentPage)
```

useEffect watching `currentPage`:
- If currentPage !== prevPage.current:
  - setDirection based on comparison
  - setIsTransitioning(true)
  - setTimeout 300ms: setDisplayPage(currentPage), setIsTransitioning(false)
  - prevPage.current = currentPage

Animation classes (tw-animate-css):
- Forward enter: `animate-in slide-in-from-right fade-in duration-300`
- Forward exit: `animate-out slide-out-to-left fade-out duration-300`
- Backward enter: `animate-in slide-in-from-left fade-in duration-300`
- Backward exit: `animate-out slide-out-to-right fade-out duration-300`

Page rendering structure:
```tsx
<div className="relative overflow-hidden">
  {isTransitioning && (
    <div className={`absolute inset-0 ${exitAnimationClass}`}>
      {renderPage(displayPage)}
    </div>
  )}
  <div className={isTransitioning ? enterAnimationClass : ''}>
    {renderPage(isTransitioning ? currentPage : displayPage)}
  </div>
</div>
```

Extract `renderPage(pageIndex: number)` function that returns the JSX for each page:
- Page 0: PlatformSelector + SpeciesSelector (unchanged)
- Page 1: AnalyteSelectionPanel (redesigned in Plan 02)
- Page 2: CalculatorPanel + PlatePanel (PlatePanel now interactive)

Keep the navigation bar (Previous/Next buttons) OUTSIDE the transition container so it doesn't animate.

Keep the max-w-4xl container. Keep the header and footer unchanged.

**Important:** During transitions, BOTH pages are in the DOM. The old page has `absolute inset-0` positioning (overlays but slides out), the new page has normal flow (slides in). After transition, the old page unmounts.

**Update `PlatePanel.tsx` to wire interactive well selection:**

This is the key integration step. PlatePanel now uses useWellSelection + plateStore to make the plate grid interactive.

Changes:
- Import `useWellSelection` from `../hooks/useWellSelection`
- Import `usePlateStore` (already imported from Plan 04)
- Import `STANDARD_COLS` from `../../../../../shared/types/plate`
- Get plateStore state: `replicateMode`, `getPlateWells(activePlate)`, `setWellRange`, `toggleWell`
- Initialize useWellSelection:
  ```typescript
  const { hoveredWells, handleMouseDown, handleMouseEnter, handleMouseUp } = useWellSelection({
    standardCols: STANDARD_COLS,
    replicateMode: plateStore.replicateMode,
    filledWells: plateStore.getPlateWells(activePlate),
    onSelectionChange: (wellIds, action) => {
      if (action === 'add') {
        plateStore.setWellRange(activePlate, wellIds, true)
      } else {
        plateStore.setWellRange(activePlate, wellIds, false)
      }
    }
  })
  ```
- Pass interactive props to PlateGrid:
  ```tsx
  <PlateGrid
    wells={currentLayout.wells}
    selectedWells={plateStore.getPlateWells(activePlate)}
    hoveredWells={hoveredWells}
    standardCols={STANDARD_COLS}
    onCellMouseDown={handleMouseDown}
    onCellMouseEnter={handleMouseEnter}
    onCellMouseUp={handleMouseUp}
  />
  ```

The PlateGrid now renders in interactive mode: wells respond to clicks and drags, selection state persists in plateStore, visual feedback shows selected (green) and hovered (blue) wells.

**Note on well state visualization:** The wells array from `usePlateLayout()` provides the base layout (standards, empty). The `selectedWells` prop from plateStore provides the filled/assigned state. The PlateGrid/WellCell should show a well as "filled" if it's in selectedWells, regardless of the wells array type (which may still say "empty" if the user manually assigned it).
