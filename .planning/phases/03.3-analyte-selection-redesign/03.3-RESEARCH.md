# Phase 3.3: Selection UX Redesign - Research

**Researched:** 2026-02-04
**Domain:** Interactive grid selection, wizard transitions, Zustand editable state, React 18 + Tailwind v4
**Confidence:** HIGH

## Summary

This phase redesigns two wizard pages (Page 2: Analyte Selection, Page 3: Sample/Plate Assignment) and adds smooth page transitions. The primary technical challenges are: (1) building Excel-like click-drag selection on a 96-well plate grid, (2) synchronizing a slider+number field with plate state, (3) implementing wizard slide transitions, and (4) managing bidirectional state between sample count and editable plate wells.

The existing codebase uses React 18.3.1, Zustand 5.x, Tailwind CSS v4 with tw-animate-css, and has no animation library installed. The plate grid is currently a read-only visualization (`PlateGrid.tsx`, `WellCell.tsx`) that derives layout from `usePlateLayout` hook. The redesign makes this grid interactive and editable. There are also bugs to fix: standards are incorrectly placed in columns 10-12 instead of 1-3, and duplicates logic is wrong.

**Primary recommendation:** Build the 96-well plate selection as a custom hook (`useWellSelection`) using mousedown/mousemove/mouseup events with `useRef` for drag state. Use `tw-animate-css` slide classes for page transitions without adding new dependencies. Restructure the plate Zustand store to hold editable well state with auto-fill as the default entry point, keeping manual editing as an override.

### Pattern 1: Custom Well Selection Hook (`useWellSelection`)
**What:** A React hook that manages mouse-based grid cell selection with click, drag, Ctrl+click, and Shift+click support.
**When to use:** For the interactive 96-well plate on Page 3.
**Why custom, not library:** The grid is a fixed 8x12 layout with known cell positions. No need for bounding-rect calculations or arbitrary element selection. Pure coordinate math is simpler and more performant.

**Example:**
```typescript
// Source: Custom implementation based on standard mouse event patterns
import { useRef, useCallback, useEffect, useState } from 'react'

interface CellCoord {
  row: number  // 0-7
  col: number  // 0-11
}

interface UseWellSelectionOptions {
  rows: number
  cols: number
  standardCols: number[]  // columns that cannot be selected (1-3 for standards)
  replicateMode: 'singles' | 'duplicates'
  onSelectionChange: (wells: Set<string>) => void
}

interface UseWellSelectionReturn {
  selectedWells: Set<string>
  hoveredWells: Set<string>  // preview during drag
  handleMouseDown: (row: number, col: number, event: React.MouseEvent) => void
  handleMouseEnter: (row: number, col: number) => void
  handleMouseUp: () => void
  clearSelection: () => void
  fillSequential: (sampleCount: number) => void
}

export function useWellSelection(options: UseWellSelectionOptions): UseWellSelectionReturn {
  const { rows, cols, standardCols, replicateMode, onSelectionChange } = options

  // Use refs for drag state to avoid re-renders on every mouse event
  const isDragging = useRef(false)
  const dragStart = useRef<CellCoord | null>(null)
  const lastClicked = useRef<CellCoord | null>(null)

  const [selectedWells, setSelectedWells] = useState<Set<string>>(new Set())
  const [hoveredWells, setHoveredWells] = useState<Set<string>>(new Set())

  // Convert row/col to well ID (e.g., "A1")
  const toWellId = (row: number, col: number): string => {
    return `${String.fromCharCode(65 + row)}${col + 1}`
  }

  // Check if a column is a standard column (not selectable)
  const isStandardCol = (col: number): boolean => {
    return standardCols.includes(col + 1)  // standardCols are 1-indexed
  }

  // Get all cells in a rectangular range
  const getCellsInRange = useCallback((start: CellCoord, end: CellCoord): Set<string> => {
    const cells = new Set<string>()
    const minRow = Math.min(start.row, end.row)
    const maxRow = Math.max(start.row, end.row)
    const minCol = Math.min(start.col, end.col)
    const maxCol = Math.max(start.col, end.col)

    for (let r = minRow; r <= maxRow; r++) {
      for (let c = minCol; c <= maxCol; c++) {
        if (!isStandardCol(c)) {
          cells.add(toWellId(r, c))
          // In duplicates mode, also select the paired well
          if (replicateMode === 'duplicates') {
            const paired = getDuplicatePair(r, c)
            if (paired) cells.add(toWellId(paired.row, paired.col))
          }
        }
      }
    }
    return cells
  }, [standardCols, replicateMode])

  const handleMouseDown = useCallback((row: number, col: number, event: React.MouseEvent) => {
    if (isStandardCol(col)) return

    isDragging.current = true
    dragStart.current = { row, col }

    if (event.shiftKey && lastClicked.current) {
      // Shift+click: extend selection from last click
      const range = getCellsInRange(lastClicked.current, { row, col })
      setSelectedWells(prev => new Set([...prev, ...range]))
    } else if (event.ctrlKey || event.metaKey) {
      // Ctrl+click: toggle individual well
      const wellId = toWellId(row, col)
      setSelectedWells(prev => {
        const next = new Set(prev)
        if (next.has(wellId)) next.delete(wellId)
        else next.add(wellId)
        return next
      })
    } else {
      // Plain click: start new selection
      const wellId = toWellId(row, col)
      setSelectedWells(new Set([wellId]))
    }

    lastClicked.current = { row, col }
  }, [getCellsInRange])

  const handleMouseEnter = useCallback((row: number, col: number) => {
    if (!isDragging.current || !dragStart.current) return
    const range = getCellsInRange(dragStart.current, { row, col })
    setHoveredWells(range)
  }, [getCellsInRange])

  const handleMouseUp = useCallback(() => {
    if (isDragging.current && hoveredWells.size > 0) {
      setSelectedWells(prev => new Set([...prev, ...hoveredWells]))
      setHoveredWells(new Set())
    }
    isDragging.current = false
    dragStart.current = null
  }, [hoveredWells])

  // Attach mouseup to window to catch releases outside the grid
  useEffect(() => {
    const handler = () => {
      if (isDragging.current) {
        isDragging.current = false
        dragStart.current = null
        setHoveredWells(new Set())
      }
    }
    window.addEventListener('mouseup', handler)
    return () => window.removeEventListener('mouseup', handler)
  }, [])

  return { selectedWells, hoveredWells, handleMouseDown, handleMouseEnter, handleMouseUp, clearSelection, fillSequential }
}
```

### Pattern 2: Editable Plate State Store (Zustand)
**What:** A dedicated Zustand store that holds per-plate well assignments as editable state, with auto-fill as default and manual overrides.
**When to use:** For managing the bidirectional sync between sample count and plate well assignments.

**Example:**
```typescript
// Source: Zustand 5.x patterns from official docs
import { create } from 'zustand'

interface PlateState {
  // Source of truth: which wells are filled on each plate
  plates: Map<number, Set<string>>  // plateNumber -> set of filled well IDs
  activePlate: number
  sampleCount: number  // input value (can be blank = 0)
  replicateMode: 'singles' | 'duplicates'

  // Derived (computed in getters)
  getSamplesRemaining: () => number
  getTotalAssigned: () => number
  getMinPlatesNeeded: () => number

  // Actions
  setSampleCount: (count: number) => void
  autoFill: () => void  // Sequential fill across plates
  toggleWell: (plateNumber: number, wellId: string) => void
  toggleWellRange: (plateNumber: number, wellIds: Set<string>) => void
  addPlate: () => void
  removePlate: (plateNumber: number) => void
  clearPlate: (plateNumber: number) => void
  setActivePlate: (plateNumber: number) => void
}
```

**Key insight: ONE-WAY data flow with manual override.**

The state model is NOT truly bidirectional. Instead:
1. User enters `sampleCount` -> auto-fill runs -> populates plates
2. User manually edits wells -> `sampleCount` stays the same, `samplesRemaining` updates
3. `samplesRemaining = sampleCount - totalAssignedWells`
4. User can re-trigger auto-fill at any time to reset manual edits

This avoids circular update problems. The sample count is the INPUT, the plate assignments are the OUTPUT that can be manually adjusted.

### Pattern 3: Wizard Page Transitions with tw-animate-css
**What:** CSS-only slide transitions between wizard pages using tw-animate-css classes already installed.
**When to use:** For all wizard page navigation (Pages 0, 1, 2).

**Example:**
```tsx
// Approach: Keep both old and new page in DOM briefly during transition
// Use CSS animations with tw-animate-css classes

import { useState, useRef, useEffect } from 'react'

function WizardContainer({ children, currentPage }: { children: React.ReactNode[], currentPage: number }) {
  const [displayPage, setDisplayPage] = useState(currentPage)
  const [isTransitioning, setIsTransitioning] = useState(false)
  const [direction, setDirection] = useState<'left' | 'right'>('right')
  const prevPage = useRef(currentPage)

  useEffect(() => {
    if (currentPage !== prevPage.current) {
      setDirection(currentPage > prevPage.current ? 'left' : 'right')
      setIsTransitioning(true)

      // After animation completes, update displayed page
      const timer = setTimeout(() => {
        setDisplayPage(currentPage)
        setIsTransitioning(false)
      }, 300) // Match animation duration

      prevPage.current = currentPage
      return () => clearTimeout(timer)
    }
  }, [currentPage])

  // During transition, show old page sliding out + new page sliding in
  const exitClass = direction === 'left'
    ? 'animate-out slide-out-to-left fade-out duration-300'
    : 'animate-out slide-out-to-right fade-out duration-300'

  const enterClass = direction === 'left'
    ? 'animate-in slide-in-from-right fade-in duration-300'
    : 'animate-in slide-in-from-left fade-in duration-300'

  return (
    <div className="relative overflow-hidden">
      {isTransitioning && (
        <div className={`absolute inset-0 ${exitClass}`}>
          {children[displayPage]}
        </div>
      )}
      <div className={isTransitioning ? enterClass : ''}>
        {children[isTransitioning ? currentPage : displayPage]}
      </div>
    </div>
  )
}
```

### Anti-Patterns to Avoid
- **Storing selection as array instead of Set:** Use `Set<string>` for O(1) lookups when checking if a well is selected. Arrays require O(n) `includes()` calls on every render for each of 96 cells.
- **Re-rendering entire grid on each mousemove:** Use `useRef` for isDragging state, not `useState`. Only update visual state (hovered wells) on mouse enter events, not mouse move.
- **Bidirectional reactive sync:** Do NOT create a pattern where changing plate wells auto-updates sampleCount which auto-updates plate wells. This creates infinite loops. Use one-way flow: sampleCount is input, plate assignments are editable output.
- **Using conditional rendering for page transitions:** Pages must remain in the DOM during the transition animation. Use CSS opacity/transform, not `{currentPage === 1 && <Page1 />}` during transitions.
- **Adding Framer Motion or other heavy animation libraries:** tw-animate-css is already installed and provides exactly the slide-in/slide-out/fade-in/fade-out classes needed. No new dependency required.

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Slide animations | Custom CSS @keyframes | tw-animate-css classes (`animate-in`, `slide-in-from-left`, etc.) | Already installed, tree-shaken, Tailwind v4 native |
| Range slider styling | Custom slider from scratch | Native `<input type="range">` + Tailwind `accent-color` / `appearance-none` styling | Browser handles accessibility, keyboard, touch |
| Well coordinate math | Ad-hoc string parsing | Pure utility functions (row index to letter, col number to index) | Reusable, testable, avoids off-by-one errors |
| Prevent text selection during drag | Manual event handling | CSS `select-none` (Tailwind class) + `user-select: none` | One class vs complex preventDefault chains |

**Key insight:** The 96-well plate interaction IS something to hand-build as a custom hook. There is no library that fits this specific use case without massive overhead. The grid is fixed (8x12), the interaction model is well-defined (click, drag, Shift, Ctrl), and the coordinate system is simple.

## Common Pitfalls

### Pitfall 1: Stale Closure in Mouse Event Handlers
**What goes wrong:** Event handlers attached via `useEffect` capture stale state values, causing drag selection to use outdated selectedWells.
**Why it happens:** JavaScript closures capture variables at definition time. If you attach a handler in useEffect and reference state, it sees the state at the time of attachment.
**How to avoid:** Use `useRef` for mutable values needed in event handlers (isDragging, dragStart). Use `useCallback` with explicit dependencies for handlers passed as props. For the `window.addEventListener('mouseup', ...)` handler, keep it minimal - just reset drag state.
**Warning signs:** Selection works on first drag but breaks on subsequent drags. Wells from previous selections reappear.

### Pitfall 2: Off-by-One Errors in Column Numbering
**What goes wrong:** Mixing 0-indexed array positions with 1-indexed column numbers (plate columns are 1-12, but array indices are 0-11).
**Why it happens:** The existing code uses 1-indexed `COLS = [1,2,...,12]` but array access is 0-indexed (`wells[rowIndex][col - 1]`).
**How to avoid:** Establish a clear convention: well IDs use 1-indexed columns ("A1"), internal computation uses 0-indexed. Create utility functions `toWellId(row, col)` and `fromWellId(wellId)` and use them consistently.
**Warning signs:** Standards appear in wrong columns. Samples fill one column off.

### Pitfall 3: Performance Degradation from Re-rendering 96 Cells
**What goes wrong:** Every mouse movement triggers re-render of all 96 WellCell components, causing jank during drag selection.
**Why it happens:** If selectedWells or hoveredWells is a new Set on every mousemove, all cells re-render.
**How to avoid:**
1. Memoize WellCell with `React.memo` and compare only the props that matter (isSelected, isHovered, wellType).
2. Use data attributes or CSS classes for hover state rather than React state where possible.
3. Consider using `onMouseEnter` per-cell (fires once on entry) instead of `onMouseMove` on the grid (fires continuously).
**Warning signs:** Visible lag when dragging across cells. DevTools shows frequent re-renders.

### Pitfall 4: Duplicates Mode Pairing Logic
**What goes wrong:** Clicking one well in a duplicate pair does not toggle the other, or vertical pairs in column 12 are not handled.
**Why it happens:** The duplicates layout has TWO pairing modes: horizontal pairs (cols 4-5, 6-7, 8-9, 10-11) and vertical pairs (col 12 A-D maps to E-H). This is non-obvious.
**How to avoid:** Create a pure function `getDuplicatePair(row, col)` that returns the paired cell coordinates. For horizontal pairs: if col is even, pair is col-1; if odd, pair is col+1. For column 12: pair A with E, B with F, etc. Unit test this function thoroughly.
**Warning signs:** Clicking column 12 row A does nothing to row E. Dragging across duplicate pairs selects individual wells.

### Pitfall 5: Transition Animation with Conditional Rendering
**What goes wrong:** Page slides in but the old page just disappears instantly (no slide-out animation).
**Why it happens:** React unmounts the old page immediately when `currentPage` changes, before any exit animation can play.
**How to avoid:** Keep both pages in the DOM during the transition period. Use a two-phase approach: (1) start transition, render both old and new pages with animation classes, (2) after animation duration, unmount old page. Use `setTimeout` matching the CSS animation duration.
**Warning signs:** Pages just appear/disappear. Only enter animation works, not exit.

### Pitfall 6: Slider/Number Field Desynchronization with Blank Field
**What goes wrong:** User clears the number field (blank), slider jumps to 0, or typing "1" "0" "0" causes three separate state updates with values 1, 10, 100.
**Why it happens:** The number input fires onChange on every keystroke. A blank field returns NaN or empty string.
**How to avoid:** Use a local string state for the text field display value, separate from the numeric state. Parse and sync to numeric state on blur or Enter key. While typing, only the display string updates. The slider always reflects the committed numeric value.
**Warning signs:** Slider jumps while typing. Clearing the field causes errors. Can't type multi-digit numbers smoothly.

### Example 2: Sample Count Slider + Number Field
```tsx
// Composite input: slider synced with editable number field
import { useState, useCallback } from 'react'

interface SampleCountInputProps {
  value: number
  max: number
  onChange: (value: number) => void
}

export function SampleCountInput({ value, max, onChange }: SampleCountInputProps) {
  // Local string state for the text field to handle blank/intermediate values
  const [displayValue, setDisplayValue] = useState(value === 0 ? '' : String(value))

  const commitValue = useCallback((raw: string) => {
    const parsed = parseInt(raw, 10)
    if (isNaN(parsed) || parsed < 0) {
      onChange(0)
      setDisplayValue('')
    } else {
      const clamped = Math.min(parsed, max)
      onChange(clamped)
      setDisplayValue(clamped === 0 ? '' : String(clamped))
    }
  }, [max, onChange])

  const handleSliderChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const val = Number(e.target.value)
    onChange(val)
    setDisplayValue(val === 0 ? '' : String(val))
  }

  const handleFieldChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    // Allow free typing, only store as display string
    setDisplayValue(e.target.value)
  }

  const handleFieldBlur = () => {
    commitValue(displayValue)
  }

  const handleFieldKeyDown = (e: React.KeyboardEvent) => {
    if (e.key === 'Enter') {
      commitValue(displayValue)
    }
  }

  return (
    <div className="flex items-center gap-4">
      <input
        type="number"
        value={displayValue}
        onChange={handleFieldChange}
        onBlur={handleFieldBlur}
        onKeyDown={handleFieldKeyDown}
        placeholder="0"
        min={0}
        max={max}
        className="w-24 px-3 py-2 border border-[var(--color-border)] rounded-md text-sm focus:outline-none focus:ring-2 focus:ring-[var(--color-primary)]"
      />
      <input
        type="range"
        min={0}
        max={max}
        value={value}
        onChange={handleSliderChange}
        className="flex-1 h-2 accent-[var(--color-primary)]"
      />
    </div>
  )
}
```

### Example 4: Duplicates Pair Lookup Function
```typescript
// Pure function: given a cell, return its duplicate pair partner
export function getDuplicatePair(
  row: number,  // 0-indexed (0=A, 7=H)
  col: number   // 0-indexed (0=col1, 11=col12)
): { row: number; col: number } | null {
  const col1Indexed = col + 1

  // Standards columns (1-3) have no pairs
  if (col1Indexed <= 3) return null

  // Column 12 vertical pairs: A<->E, B<->F, C<->G, D<->H
  if (col1Indexed === 12) {
    if (row < 4) return { row: row + 4, col }
    if (row >= 4) return { row: row - 4, col }
  }

  // Horizontal pairs: 4-5, 6-7, 8-9, 10-11
  if (col1Indexed >= 4 && col1Indexed <= 11) {
    // Pairs are: (4,5), (6,7), (8,9), (10,11) -> (even,odd) in 1-indexed
    if (col1Indexed % 2 === 0) {
      return { row, col: col + 1 }  // even col -> paired with next
    } else {
      return { row, col: col - 1 }  // odd col -> paired with previous
    }
  }

  return null
}
```

## Open Questions

Things that couldn't be fully resolved:

1. **Maximum sample count for the slider**
   - What we know: The slider needs a max value. Current code validates against `plateCount * wellsPerPlate`. With editable plates, the max is less clear.
   - What's unclear: Should there be a hard max (e.g., 1000 samples = ~14 plates), or should the slider be unbounded with the number field allowing any value?
   - Recommendation: Set a reasonable max (e.g., 500 or 1000). The slider provides quick adjustment; the number field allows typing higher values which auto-create plates.

2. **Auto-fill trigger timing**
   - What we know: When sample count changes, plates should auto-fill sequentially.
   - What's unclear: Should auto-fill run on every keystroke while typing, or only on commit (blur/Enter)? If the user has manually edited wells, should changing sample count reset manual edits?
   - Recommendation: Auto-fill only on committed value changes (blur/Enter/slider release). Show a confirmation or "Reset to auto-fill" button if user has manual edits.

3. **Page transition direction when going directly to a non-adjacent page**
   - What we know: Pages are sequential (0, 1, 2) with forward/backward navigation.
   - What's unclear: Can the user jump from page 0 to page 2 directly (e.g., via breadcrumb)?
   - Recommendation: Keep sequential navigation only (Next/Previous buttons). Transition direction is determined by newPage > oldPage.

4. **Touch support for well selection**
   - What we know: This is an Electron desktop app, so touch is unlikely. The context mentions mouse interactions only.
   - What's unclear: Whether any touch devices (touchscreen laptops) need support.
   - Recommendation: Skip touch support for now. Mouse events are sufficient for Electron desktop.
