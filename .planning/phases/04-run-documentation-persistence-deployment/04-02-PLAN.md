### Step 3.1 — `src/renderer/src/stores/runStore.ts`

Follow the `platformStore.ts` shape (loadFoo / selectFoo / isLoading / error). Differences:

- State: `runs: RunRecord[]`, `currentRunId: string | null`, `isLoading: boolean`, `saveStatus: 'idle' | 'saving' | 'success' | 'error'`, `error: string | null`.
- `fetchRuns()` → `window.electronAPI.run.getAll()` and store.
- `saveCurrentRun(metadata: { userName; operatorName; runDate; sampleType; hamiltonAssignment?; tubeBlockPositions?; troughPositions? })` — uses `useRunSnapshot` logic imported as a plain function (NOT a hook, since this runs outside React). Call the function to build the `RunCreate` payload, invoke `window.electronAPI.run.create(payload)`, prepend the result to `runs`, flip `saveStatus` through `'saving'` → `'success'`, clear after ~2s or on next save.
- `loadRun(id: string)` — fetches via `window.electronAPI.run.getById(id)`, then orchestrates rehydration (Step 3.2).
- `deleteRun(id: string)` — calls `window.electronAPI.run.delete(id)`, filters local list.
- `clearCurrentRun()` — sets `currentRunId: null` (does NOT clear other stores; the Reset button in calculator already exists for that).

**Type safety:** Import `RunRecord` and `RunCreate` from `src/shared/types/run.ts` (created by plan 04-01). If those types are missing when this task runs, halt and flag to the user that plan 04-01 did not land.

### Step 3.2 — rehydration inside `loadRun`

Task 1's research output tells you the exact order. Expected shape:

```ts
// inside loadRun, after fetching `run`:
const platform = usePlatformStore.getState()
const selection = useSelectionStore.getState()
const calculator = useCalculatorStore.getState()

// 1. Select platform (triggers species load in the selector component; we also need species now)
platform.selectPlatform(run.platformId)

// 2. Load species list for this platform, then select the stored species
await selection.loadSpecies(run.platformId)
selection.selectSpecies(run.speciesId)

// 3. Load panels + analytes for (platform, species)
await selection.loadPanelsAndAnalytes(run.platformId, run.speciesId)

// 4. Select panel (if any) — this is async; await
if (run.panelId) {
  await selection.selectPanel(run.panelId)
}

// 5. Toggle each single analyte by id (only those not already in the panel)
for (const analyteId of run.analyteIds) {
  // toggleSingleAnalyte no-ops if already in panel, which is the behavior we want
  selection.toggleSingleAnalyte(analyteId)
}

// 6. Calculator: replicateMode first (affects wells-per-plate), then sampleCount.
//    Both propagate to plateStore via existing calculatorStore plumbing (see 03.3-04-SUMMARY).
calculator.setReplicateMode(run.replicateMode)
calculator.setSampleCount(run.sampleCount)
// requestType is DERIVED by selectionStore.getRequestType() — do not set it manually.

set({ currentRunId: run.id })
```

**Plate grid note:** We do NOT restore per-well `plateStore.plates` in v1. The auto-fill cascade from `setSampleCount` produces the same default layout the operator got when they built the run. If the operator made manual well adjustments before saving, those are lost on reload — acceptable for v1 per DOCM-01's scope (the stored `hamiltonAssignment` / `tubeBlockPositions` / `troughPositions` are paper-form metadata, not the in-app grid). Confirm with the human-verify checkpoint.

### Step 3.3 — `src/renderer/src/features/run/hooks/useRunSnapshot.ts`

Export TWO things:

```ts
export function buildRunSnapshot(metadata: MetadataFields): RunCreate | { error: string }
export function useRunSnapshot(): { canSave: boolean; reason: string | null; build: (m: MetadataFields) => RunCreate | { error: string } }
```

- `buildRunSnapshot` is a pure function that calls `.getState()` on each store (so it works outside React), assembles a `RunCreate`, and returns an error if the state is incomplete (no platform, no species, no analytes, sampleCount <= 0, or `calculator.validationError` is set).
- `useRunSnapshot` wraps it for the form: subscribes to the stores via selectors for the `canSave` flag so the Save button reactively enables/disables.

Fields assembled:

| Field (RunCreate) | Source |
|---|---|
| `userName`, `operatorName`, `runDate`, `sampleType`, `hamiltonAssignment`, `tubeBlockPositions`, `troughPositions` | form metadata arg |
| `platformId` | `usePlatformStore.getState().selectedPlatformId` |
| `speciesId` | `useSelectionStore.getState().selectedSpeciesId` |
| `panelId` | `useSelectionStore.getState().selectedPanelId` (nullable) |
| `analyteIds` | `useSelectionStore.getState().getAllSelectedAnalytes().map(a => a.id)` |
| `sampleCount` | `useCalculatorStore.getState().sampleCount` |
| `replicateMode` | `useCalculatorStore.getState().replicateMode` |
| `numberOfPlates` | `usePlateStore.getState().getPlateCount()` |
| `numberOfSamples` | same as `sampleCount` (alias — confirm schema from 04-01; if schema has both, set both) |
