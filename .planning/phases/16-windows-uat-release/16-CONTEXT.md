### Build targets

- **D-16-03:** **x64 only** for v1.0. Drop the `x64 + arm64` requirement from Phase 16 SC #1 in ROADMAP.md.
- Rationale — the lab PC is x64; arm64 has never been built or signed in this project; shipping an arm64 binary that has zero physical-hardware verification is worse than not shipping it. Honors the spirit of the original SC ("works on Windows") without the dead-weight risk.
- **D-16-04:** Capture arm64 as a follow-up backlog item (`999.x — arm64 Windows build`) tied to "actual arm64 hardware is in the lab" trigger. NOT a v1.0 release blocker.

### UAT script structure

- **D-16-05:** **Hybrid format** — three sections in `16-SMOKE-TEST-GUIDE.md`:
  - **Section A: End-to-end flow** (Phase 4.1 pattern, ~15 numbered steps) — install fresh .exe → import `templates/panels/all-panels.xlsx` → select platform/species/panel → pick premixes + singles → enter Old Beads / Old Antibodies / Number of Setups → verify calc output against hand calc → save run → reopen → verify snapshot fidelity. Simulates a realistic operator run.
  - **Section B: Per-requirement acceptance matrix** — one row per `SMK3-01` through `SMK3-17`, each scored `Pass / Fail / N/A` with a one-line evidence note. Catches branches the E2E flow doesn't exercise (e.g., a panel without a 1× premix triggers the Values-table diluent fallback; SMK3-07 row must explicitly test this).
  - **Section C: Free-text observations + bugs found** — anything the script didn't anticipate.
- **D-16-06:** Test fixture data — use `templates/panels/all-panels.xlsx` (the 16-panel + Table sheet generated by Phase 13-02) as the canonical UAT fixture. NOT pre-loaded in the installer; the operator imports it as Step 2 of Section A to exercise the import flow. (See `<gaps>` below for the 16-vs-17 panel count discrepancy.)
- **D-16-07:** Hand-calc reference — Phase 16 plan MUST produce a hand-calc cheat sheet (`16-HAND-CALC.md`) with PRD worked example + 2–3 additional panels' expected outputs, so the operator can verify Section A Step 6 without spreadsheet-on-the-side math.
- **D-16-08:** Pass criterion — every Section A step must pass AND every SMK3-XX row must be `Pass` or have an explicit `N/A` justification. A single `Fail` blocks the v1.0.0 tag and triggers a Phase 16.1 fix-loop (Phase 4.1 precedent).
- **D-16-09:** Outcomes recorded in `16-SMOKE-TEST-RETEST.md` with `## Overall: PASS` at the bottom on success.

### Phase 15 UAT-item integration (added on resume)

- **D-16-14:** **Section B accepts decision rows alongside SMK3-XX requirement rows.** Phase 15's override badge (`D-15-08`) is user-visible behavior tied to a decision, not a PRD requirement — it gets its own dedicated Section B row labeled `D-15-08 override badge`. This sets the precedent: any phase that introduces user-visible behavior via a decision (not just a requirement) gets a Section B row keyed to that decision ID.
- **D-16-15:** **Phase 16 plan adds a fixture-coverage audit step** before the build is cut. Must verify `templates/panels/all-panels.xlsx` contains:
  - (a) at least one premix panel where the audit-trail render exercises all 4 input/intermediate/output/diluent blocks (Phase 15 UAT item #1 — SMK3-15, SMK3-12)
  - (b) a seed-script step that inserts a synthetic pre-Phase-15 run into the installed DB (`calculation_rules_version = NULL`) so the operator can verify the historical-run banner (Phase 15 UAT item #2 — SMK3-16). Lab PC may not have a real pre-Phase-15 run; do NOT skip this fixture step.
  - (c) at least one panel where Old Beads can credibly exceed the 20% cap so the operator can trigger the override modal (Phase 15 UAT item #3 — D-15-08)
  - (d) a panel whose SAPE row has concentration = 1 so PE volume equals total assay volume (Phase 15 UAT item #4 — SMK3-17)
- The planner enumerates the actual panel from `all-panels.xlsx` that satisfies each requirement and pins it into the Section A walkthrough.
- The seed script for (b) lives in `scripts/seed-legacy-run.ts` (TO BE CREATED) and runs as an explicit `16-SMOKE-TEST-GUIDE.md` Section A pre-step.

### Phase 15.1 gap closure (mandatory before Phase 16 build)

- **D-16-16:** **Phase 15.1 is a hard precondition** for the Phase 16 build step. Phase 15.1 closes three Phase 15 code-review warnings that affect audit-trail integrity and round-trip fidelity. Phase 16 plan MUST verify Phase 15.1 is `[x]` complete in ROADMAP before `npm run build:win` runs.
- **D-16-17:** Phase 15.1 scope (single gap-closure phase, bundle all three fixes; planner can split into 1–3 plans):
  - **WR-02 fix (audit-trail integrity):** `buildRunSnapshot` MUST NOT silently swallow `getWithReagents` returning null. Either surface an error to the user (e.g., "Run cannot be saved — master panel not found") OR skip writing `calculationRulesVersion='smoke3'` when snapshot fields are empty (i.e., the run looks like a legacy custom-assay save). A run with `calculationRulesVersion='smoke3'` but empty snapshot fields is data corruption from the audit-trail render's perspective.
  - **WR-01 fix (round-trip fidelity):** `loadRun` restores `oldBeadsOverride` and `oldAntibodiesOverride` into `calculatorStore` on reopen, so the form-side override badge state is consistent with the audit-trail render.
  - **WR-06 fix (audit-trail completeness):** Derive the 6 hardcoded `—` rows (Raw bead/antibody volume, New beads/antibodies, Total bead/antibody volume) from the snapshot data + existing calculator helpers (`calculateTotalWells`, `calculateRawVolume`, etc.). No new persisted fields needed — these are computed from already-snapshotted values + the old-reagent subtraction pipeline. WR-06's own analysis in `15-REVIEW.md` describes the derivation.
- **D-16-18:** Phase 15.1 success criteria:
  - All 3 fixes ship behind the existing `'smoke3'` `calculationRulesVersion` (no new version marker — legacy runs are unaffected)
  - Full test suite green (`npm test -- --run`) including new round-trip tests for the override-flag restoration
  - `npm run typecheck` green
  - No code-review re-run gate (15.1 is a tactical fix sweep, not a full phase); but if /gsd-code-review is run, all three WRs should be resolved
