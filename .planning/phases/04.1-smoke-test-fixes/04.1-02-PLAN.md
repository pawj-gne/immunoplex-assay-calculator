<objective>
Fix BUG-02 (critical — data loss): adding a second plate or changing sample count erases plate 1's operator-edited well assignments.

Per PATTERNS.md §BUG-02, `addPlate` itself is correct — it spreads existing plates. The regression is in `autoFill`, which rebuilds `plates` from scratch every time it's called. `setSampleCount` and `setReplicateMode` both cascade to `autoFill`, so any downstream re-trigger (e.g. bumping sample count after editing plate 1) wipes edits.

Purpose: Operators must be able to fill plate 1, add plate 2, and trust that plate 1 is still there. Per D-4.1-02: "Adding a plate MUST NOT erase any existing plate's well assignments."

Output: `plateStore.autoFill` rewritten to preserve any existing plate's wells. It populates empty plate slots (plates that don't exist yet, or exist with an empty Set) but LEAVES non-empty plate slots alone. If existing plates don't cover `sampleCount`, an overflow loop appends new plates and fills them until all samples have a home. Three other entry points (`reset`, `loadPlates`, explicit user actions) keep their existing destructive-replace semantics — only `autoFill` becomes non-destructive.

This plan depends on 04.1-01 landing first — both plans edit `plateStore.ts` and this plan's implementation copies 04.1-01's column-major duplicate loop shape. Wave 2.
</objective>

```typescript
autoFill: () => {
  const { sampleCount, replicateMode, plates: existingPlates, activePlate } = get()

  if (sampleCount <= 0) {
    // sampleCount = 0 is the explicit "wipe" signal — operator zeroed the count.
    set({ plates: { 1: new Set<string>() }, activePlate: 1 })
    return
  }

  const wellsPerPlate =
    replicateMode === 'singles' ? UNKNOWN_WELLS_SINGLES : UNKNOWN_WELLS_DUPLICATES
  const minPlates = Math.ceil(sampleCount / wellsPerPlate)

  // Start from existing plates so operator edits on any non-empty plate are preserved.
  // We only write to plate slots that are missing or empty.
  const newPlates: Record<number, Set<string>> = { ...existingPlates }

  // Count samples already represented by existing non-empty plates.
  // In duplicates mode, two wells = one sample, so divide by 2.
  let samplesAssigned = 0
  for (const wells of Object.values(newPlates)) {
    if (wells.size > 0) {
      samplesAssigned +=
        replicateMode === 'duplicates' ? Math.floor(wells.size / 2) : wells.size
    }
  }

  // Helper: fill a single plate's Set<string> up to `sampleCount`, incrementing
  // samplesAssigned. Uses the column-major duplicates loop landed by Plan 04.1-01.
  // Returns when samplesAssigned >= sampleCount or the plate is full.
  const fillPlate = (plateWells: Set<string>): void => {
    if (replicateMode === 'singles') {
      for (const col of UNKNOWN_COLS_ORDERED) {
        for (let rowIndex = 0; rowIndex < ROWS.length; rowIndex++) {
          if (samplesAssigned >= sampleCount) return
          plateWells.add(wellId(rowIndex, col))
          samplesAssigned++
        }
      }
    } else {
      // Duplicates mode — column-major per Plan 04.1-01 (outer pair, inner row)
      for (const [col1, col2] of DUPLICATE_HORIZONTAL_PAIRS) {
        for (let rowIndex = 0; rowIndex < ROWS.length; rowIndex++) {
          if (samplesAssigned >= sampleCount) return
          plateWells.add(wellId(rowIndex, col1))
          plateWells.add(wellId(rowIndex, col2))
          samplesAssigned++
        }
      }

      // Col 12 vertical-split block — unchanged from pre-04.1 implementation
      for (let topRow = 0; topRow < 4; topRow++) {
        if (samplesAssigned >= sampleCount) return
        plateWells.add(wellId(topRow, DUPLICATE_VERTICAL_COL))
        plateWells.add(wellId(topRow + 4, DUPLICATE_VERTICAL_COL))
        samplesAssigned++
      }
    }
  }

  // Ensure at least `minPlates` plate slots exist (create empty Sets for any missing).
  for (let p = 1; p <= minPlates; p++) {
    if (!newPlates[p]) {
      newPlates[p] = new Set<string>()
    }
  }

  // Fill only plates that are CURRENTLY empty, walking p=1..minPlates.
  // Non-empty plates are preserved (operator or prior auto-fill touched them).
  for (let p = 1; p <= minPlates; p++) {
    if (samplesAssigned >= sampleCount) break
    const plateWells = newPlates[p]
    if (plateWells.size > 0) continue // skip non-empty plates — preserve operator edits
    fillPlate(plateWells)
  }

  // Overflow: if existing non-empty plates meant the main loop skipped slots and
  // samplesAssigned still trails sampleCount, append new plates and fill them
  // until every sample has a home. This handles Scenario D from §behavior above:
  // plates={1: full, 2: empty}, bump sampleCount 32→33 — sample 33 needs a home
  // and plate 1 is non-empty, so overflow creates/uses plate 2 or plate 3.
  let nextPlate =
    Object.keys(newPlates).length > 0
      ? Math.max(...Object.keys(newPlates).map(Number)) + 1
      : 1
  while (samplesAssigned < sampleCount) {
    // Prefer any existing empty slot (e.g. operator-added empty plate 2)
    // before appending a new one, so we don't pointlessly grow the record.
    const existingEmptySlot = Object.keys(newPlates)
      .map(Number)
      .sort((a, b) => a - b)
      .find((n) => newPlates[n].size === 0)
    const targetPlate = existingEmptySlot !== undefined ? existingEmptySlot : nextPlate++
    if (!newPlates[targetPlate]) newPlates[targetPlate] = new Set<string>()
    fillPlate(newPlates[targetPlate])
  }

  // activePlate stays as-is unless it now points past the last plate slot.
  const maxPlate = Math.max(...Object.keys(newPlates).map(Number))
  const validActivePlate = activePlate > maxPlate ? 1 : activePlate

  set({ plates: newPlates, activePlate: validActivePlate })
},
```

Key invariants:
1. `const newPlates = { ...existingPlates }` preserves every existing plate's Set reference.
2. `if (plateWells.size > 0) continue` skips any plate the operator (or prior auto-fill) has touched.
3. `samplesAssigned` is seeded from existing plate contents, so we don't double-fill.
4. The `fillPlate` helper contains the column-major duplicates loop body from Plan 04.1-01, extracted so it can be reused by both the main loop and the overflow loop without copy-paste.
5. The overflow `while` loop guarantees progress: `fillPlate` increments `samplesAssigned` by at least 1 per plate (a plate holds ≥1 sample), so the loop always terminates. If an edge case ever produced a non-incrementing call, the loop would break out via `samplesAssigned >= sampleCount` once the plate filled; in the contrived case where `wellsPerPlate === 0` the outer math already would have returned via `sampleCount <= 0`.
6. The overflow loop prefers existing empty plate slots over appending new ones — this matches the "adding a plate then bumping samples" operator workflow (Scenario D).

Do NOT touch `addPlate`, `reset`, `loadPlates`, `clearPlate`, `removePlate`, `toggleWell`, or `setWellRange`. Those paths already do the right thing.
