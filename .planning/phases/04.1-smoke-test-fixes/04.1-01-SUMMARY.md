### Manual layout traces (Task 2)

Design-verification traces for the post-fix algorithm. Each trace lists the wells that will be present in `plateWells` for the given `sampleCount` under `replicateMode='duplicates'`. Cross-reference these against D-4.1-01's locked layout diagram when executing the Windows retest (Plan 04.1-05).

Algorithm under test:

```
outer: for (const [col1, col2] of [[4,5],[6,7],[8,9],[10,11]])
  inner: for (rowIndex = 0..7)  // A=0 .. H=7
    if (samplesAssigned >= sampleCount) break
    add(row, col1); add(row, col2); samplesAssigned++
  if (samplesAssigned >= sampleCount) break outer
// then col-12 vertical block:
if (samplesAssigned < sampleCount)
  for (topRow = 0..3) { add(top, 12); add(top+4, 12); samplesAssigned++ }
```

Note: `samplesAssigned` is a single counter shared across plates; per-plate iteration resumes from the current count. Each plate independently runs the full horizontal+vertical fill loops starting from a fresh `plateWells` set.

- **sampleCount=1 → plate 1:** `{A4, A5}` (sample 1 only)
- **sampleCount=8 → plate 1:** `{A4,A5,B4,B5,C4,C5,D4,D5,E4,E5,F4,F5,G4,G5,H4,H5}` (col 4 full + col 5 full, samples 1-8 in col 4 A-H)
- **sampleCount=16 → plate 1:** col 4+5 full + col 6+7 full = 32 wells: `{A4,A5,B4,B5,...,H4,H5, A6,A7,B6,B7,...,H6,H7}` (samples 1-8 in col 4 A-H, samples 9-16 in col 6 A-H, duplicates live in cols 5 and 7 at matching rows)
- **sampleCount=33 → plate 1:** cols 4-11 full (64 wells, samples 1-32) + col-12 block {A12, E12} (sample 33 vertical pair) = 66 wells total
- **sampleCount=36 → plate 1:** cols 4-11 full + col-12 block {A12,E12, B12,F12, C12,G12, D12,H12} (samples 33,34,35,36 occupying A-D with duplicates at E-H) = 72 wells total (plate 1 full capacity)
- **sampleCount=37 → plate 1:** 72 wells (full, samples 1-36 as in the sampleCount=36 trace above); **plate 2:** `{A4, A5}` (sample 37 starts the column-major fill on the new plate)

All 6 traces match D-4.1-01's locked layout exactly. Column-major ordering confirmed: within each column-pair the fill descends A→B→C→...→H before moving to the next pair. No disagreement surfaced during tracing — the loop swap in Task 1 is correct.
