# Phase 04.1 Plan 02: Fix BUG-02 autoFill destroys operator-edited plates Summary

**plateStore.autoFill rewritten to preserve existing non-empty plates — adding plate 2 (or bumping sampleCount/flipping replicateMode) no longer erases plate 1's operator-edited wells; a new fillPlate helper + overflow loop spill surplus samples into existing empty slots before appending new plates, and the sampleCount=0 wipe branch plus all other destructive entry points (reset, loadPlates, clearPlate, removePlate) are kept byte-identical.**

## Accomplishments

- `plateStore.autoFill` seeds `newPlates` from `existingPlates` (spread) instead of rebuilding from `{}`, so every existing plate's `Set<string>` reference is preserved.
- `samplesAssigned` is seeded from existing plate contents before any fill runs (duplicates: floor(size/2); singles: size), so cumulative fills never double-count.
- Main loop walks `p=1..minPlates`, filling only plates whose size is 0; non-empty plates are skipped (`if (plateWells.size > 0) continue`) — operator edits survive intact.
- New `fillPlate(plateWells)` helper contains the column-major duplicates loop body from Plan 04.1-01 (outer `DUPLICATE_HORIZONTAL_PAIRS`, inner rows A-H, then col-12 vertical-split block) and the singles column-major loop. Shared by main loop and overflow loop — zero duplication.
- Overflow `while (samplesAssigned < sampleCount)` loop handles the "addPlate then bump sampleCount" workflow: prefers existing empty slots (sorted) before appending a new plate, so the `plates` record doesn't grow pointlessly.
- `sampleCount <= 0` branch preserved byte-for-byte — the explicit operator-zero wipe signal still fires.
- `addPlate`, `reset`, `loadPlates`, `clearPlate`, `removePlate`, `toggleWell`, `setWellRange`, and all computed getters are byte-identical to pre-change code (visual diff scope confirmed by `git diff` hunks all inside the autoFill body, lines 88-195).
- D-24 contract for `loadPlates` preserved: `runStore.loadRun` still sets sampleCount+replicateMode first (cascading autoFill — now non-destructive), then calls `loadPlates` which wholesale-replaces with the saved layout.
- `npm run typecheck` passes (both node + web configs, exit 0).

## Decisions Made

Followed the plan's `<action>` snippet verbatim. Key implementation decisions (locked by plan):

1. **Spread existing plates into newPlates at entry** — preserves the Set reference for every existing plate. Skips any subsequent `if (plateWells.size > 0) continue` plate without touching its contents.
2. **Count existing samples into samplesAssigned BEFORE the fill loop** — iterates `Object.values(newPlates)`, in duplicates mode divides size by 2. This is what makes the main loop and overflow loop mathematically correct when plate 1 is already full and the operator bumps sampleCount.
3. **Extracted fillPlate helper inside autoFill** — closes over `sampleCount`/`replicateMode`/`samplesAssigned` via lexical scope; copies Plan 04.1-01's column-major duplicates body byte-for-byte (outer `DUPLICATE_HORIZONTAL_PAIRS`, inner rows). Reused by both main loop and overflow loop so the column-major shape can never diverge between the two call sites.
4. **Overflow prefers existing empty slots before appending** — `Object.keys(newPlates).map(Number).sort(...).find(n => newPlates[n].size === 0)` runs on each iteration, so if the operator added an empty plate 2 and then bumped sampleCount, sample-surplus lands on plate 2 rather than creating a fresh plate 3. Matches Scenario D expectation.
5. **activePlate guard widened from `> minPlates` to `> maxPlate`** — because overflow can grow the `plates` record past minPlates (e.g. plate 1 full + overflow appends plate 2 when minPlates was 1), the old comparator would have incorrectly reset activePlate to 1 in that case. Using `maxPlate` keeps activePlate stable whenever it still points at an existing plate.
6. **No changes to addPlate / reset / loadPlates / clearPlate / removePlate / toggleWell / setWellRange / computed getters** — the regression was scoped to autoFill; the other entry points were already correct per PATTERNS.md §BUG-02.

- Outer: `for (const [col1, col2] of DUPLICATE_HORIZONTAL_PAIRS)`
