## Decisions Made

- **D-4.1-04 enforced at store level, not component level.** Clearing `selectedSingleIds` could have been done reactively in `useAnalyteSelection` or a `useEffect` on panel change, but the store is the single source of truth for selection state and is where `selectSpecies`/`clearSpecies` already live. Clearing inside `selectPanel` keeps the invariant local to one call site.
- **Optimistic clear before await.** Placed `selectedSingleIds: []` in the pre-fetch `set(...)` rather than inside the `try` block so a `getWithAnalytes` failure still clears singles. The alternative (clear only on successful fetch) would leave the operator on Panel I singles with Panel II selected as the ID — inconsistent state that is worse than a brief empty singles list.
- **Ternary in JSX over intermediate variables.** The plan allowed either inlining `scopedAnalytes`/`sectionLabel` as JSX expressions or extracting to const declarations; chose inline ternaries since the logic is a single conditional each and a reader sees both cases adjacent to the prop name.
- **"Analytes" as the master-list label.** Per D-4.1-05, the generic label is shipped in 4.1. Vendor-specific terms like "Singleplex" (Milliplex) or "Simplex" (Thermo) ship in v2 with the xlsx upload format (cell A6 per tab).
- **`isGrayed={false}` rather than dropping the prop.** AnalyteCard's `isGrayed` is still part of its public API (used elsewhere? verified no — only AnalyteGrid imports it, and AnalyteGrid always passes false). Left the prop in place to avoid a ripple-effect change to AnalyteCard.tsx that is out of scope for this plan.

### Task 4 manual scope trace

The four scenarios below were traced against the final state of the three edited files (`selectionStore.ts`, `AnalyteGrid.tsx`, `AnalyteSelectionPanel.tsx`) on commits `d44ff60`, `96edc24`, and `6c4b126`. All four match expected outcomes.

#### Scenario A — "No Premix" master list

- **Input state:** `selectedPlatformId='milliplex-mouse'`, `selectedSpeciesId='mouse'`, `panels=[Panel I, Panel II]`, `availableAnalytes=[all mouse milliplex analytes]`, `selectedPanelId=null`, `selectedSingleIds=[]`
- **AnalyteSelectionPanel.tsx line 62-63 ternary:** `selectedPanelId && selectedPanel` → `null && ...` → `false` → falls to the right branch
- **Computed props:** `scopedAnalytes = availableAnalytes` (whole mouse master list); `sectionLabel = 'Analytes'`
- **AnalyteGrid render:** single section with header "Analytes" and one AnalyteCard per analyte in the master list. No empty-state branch taken (`scopedAnalytes.length > 0`).
- **Expected:** one section, "Analytes" label, every mouse milliplex analyte as a card. **Matches.**

#### Scenario B — Panel I selected

- **Input state:** as Scenario A but `selectedPanelId='panel-I-id'`, `selectedPanel={id:'panel-I-id', name:'Mouse Premix Panel I 32-Plex', analytes:[32 panel I analytes]}`
- **Ternary:** `'panel-I-id' && selectedPanel` → truthy → left branch
- **Computed props:** `scopedAnalytes = selectedPanel.analytes` (32 analytes); `sectionLabel = 'Mouse Premix Panel I 32-Plex'`
- **AnalyteGrid render:** single section with header "Mouse Premix Panel I 32-Plex" and 32 AnalyteCards. Panel II analytes are **not** rendered (the grid receives only Panel I's 32 ids).
- **Expected:** one section, panel name as label, 32 Panel I cards, Panel II cards absent. **Matches.**

#### Scenario C — Switch Panel I → Panel II (with stale singles)

- **Starting state:** Scenario B + operator added 2 singles → `selectedSingleIds=['single-A','single-B']`
- **Action:** operator clicks Panel II in `PremixPanelList` → `selectPanel('panel-II-id')` invoked
- **Synchronous effects inside selectPanel (lines 173-177):** `set({ panelLoading: true, panelError: null, selectedSingleIds: [] })` — singles cleared immediately, `selectedPanelId` is still 'panel-I-id' briefly until the `await` resolves
- **After `await getWithAnalytes('panel-II-id')` resolves:** `set({ selectedPanelId: 'panel-II-id', selectedPanel: <Panel II>, panelLoading: false })`
- **AnalyteSelectionPanel re-renders:** `scopedAnalytes = <Panel II analytes>`, `sectionLabel = 'Panel II name'`
- **Sidebar (SelectedAnalytesList):** `selectedSingles` (from `getSelectedSingles()` = filter `availableAnalytes` by `selectedSingleIds=[]`) → empty; `panelAnalytes` now the Panel II set
- **Expected:** Panel I analytes gone from grid; the 2 singles gone from the sidebar; Panel II section visible. **Matches.** Note: if the fetch fails, singles remain cleared (optimistic) and `panelError` is set — the operator sees an empty/error state under Panel II, which is the designed outcome per the plan's error-path clause.

#### Scenario D — Switch Panel I → "No Premix" (with stale singles)

- **Starting state:** Scenario B + 2 singles → `selectedSingleIds=['single-A','single-B']`
- **Action:** operator clicks "No Premix" → `selectPanel(null)` invoked
- **Effects inside selectPanel (lines 164-170):** `set({ selectedPanelId: null, selectedPanel: null, selectedSingleIds: [] })` then `return` — no await, synchronous
- **AnalyteSelectionPanel re-renders:** ternary falls to right branch → `scopedAnalytes = availableAnalytes` (master list), `sectionLabel = 'Analytes'`
- **Sidebar:** `selectedPanel?.name ?? null` → null (panel header gone); `panelAnalytes = getPanelAnalytes() = selectedPanel?.analytes ?? []` → empty; `selectedSingles` → empty
- **Expected:** Panel I analytes gone; the 2 singles gone; master list visible as single section titled "Analytes". **Matches.**
